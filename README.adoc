= pons-asinorum
:toc: preamble

Pons catches the mistakes that make you ask, "How did I miss that?"
Successful compilation is its starting point: wasted work, forgotten wiring,
contradictory instructions, missing figures, and claims worth a second look.
It is written in Rust, with native tree-sitter grammars for Python,
JavaScript, TypeScript, TSX and Rust. Analysing a language does not require
that language's runtime.

== Status

*Working development version: 0.1.0-dev.1.* The CLI, 27 built-in rules,
configuration, human/JSON/SARIF reports, explicit resource contracts and
positive/negative fixture gate are implemented. General Python CFG/dataflow,
source-derived typestate and the original v0.1 release acceptance gates remain
unfinished. See link:docs/AUDIT.adoc[development audit] and
link:docs/SCOPE.adoc[scope and next work]. No production or full RSR compliance
claim is made.

== Try it

[source,shell]
----
cargo build --release --locked -p pons-cli
target/release/pons scan .
target/release/pons scan . --explain
target/release/pons scan . --format sarif
target/release/pons scan . --fail-on warn
----

The default is advisory. Exit 0 means a completed scan below the selected
threshold, 1 means that threshold was reached, and 2 means invalid input,
an unavailable requested tool, or an incomplete scan. A clean result concerns
only the supported checks and files actually inspected.

Use `pons --help`, `pons scan --help`, and `pons man`. Read
link:docs/USAGE.adoc[configuration and optional tools],
link:docs/catalogue.adoc[the generated rule catalogue], and
link:build/container/README.adoc[offline container operation].

== Evidence without a lecture

A finding gives a location and a practical explanation. `--explain` adds the
technical evidence and conditions under which it may be intentional.
`HEURISTIC` is a pattern worth reviewing; `PROTOCOL` is a consequence of a
supplied contract within its stated scope; `SPECULATIVE` is a weaker prompt,
shown as a note. `DATAFLOW` is reserved for the planned flow analysis.
Every built-in rule must pass both positive and negative fixtures.

You can dismiss a rule for one program, path or occurrence. There is no
universal rule that eggs must be linear, that all loops must terminate, or
that every large benchmark improvement is false. Project contracts state
intent explicitly. For example, a loop needing 2245 eggs with only 4 allocated
reports a conditional shortfall of 2241 eggs.

== Companions

https://github.com/hyperpolymath/panic-attack[panic-attack] remains a separate
security and robustness scanner. Exchange separate SARIF runs; do not flatten
their evidence or require one executable to run the other.
`pons challenge FILE` can explicitly invoke an installed
https://github.com/hyperpolymath/invariant-path[Invariant Path] for further
claim review without writing or accepting its annotations.

https://github.com/metadatastician/authority-watch[Authority Watch] is a
candidate source for reviewed specification changes, not an automatic rule
publisher. https://github.com/hyperpolymath/lol[LOL] can inform locale naming;
Pons currently accepts an explicit local catalogue import.
https://github.com/hyperpolymath/kitchenspeak[KitchenSpeak] provides the teaching
vocabulary for optional resource/type examples. See
link:docs/INTEROPERABILITY.adoc[integration boundaries and verified interfaces].

== Development

Rust 1.97.1 and Just 1.56.0 are recorded in the toolchain files. Cargo commands
work independently of Just. Run `just check`, `just e2e`, and `just bench`.
`just docs` additionally needs Asciidoctor. Python and TypeScript examples are stored as JSON
strings and decoded by Rust falsifier tests, in accordance with the estate's
fixture policy. They are data, not project implementation.

The accepted substrate and original milestone plan remain in
link:docs/PLAN.adoc[PLAN], with current amendments in
link:docs/adr/0005-rookie-scanner-development.adoc[ADR-0005].
