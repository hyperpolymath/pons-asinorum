*pons-asinorum* — after the _pons asinorum_ (Euclid I.5, the "bridge of asses"), the
historical test that separates real understanding from rote. An
evidence-conscious structural, dataflow and protocol analyser for *dead work*,
*self-contradiction*, unsafe value flows and broken operation-order contracts.
Each finding states what supports it and where the analysis stops.

Design companion to
https://github.com/hyperpolymath/panic-attack[panic-attack]: its security and
resilience analysis complements Pons's narrow structural and contract models.
They exchange versioned evidence while retaining independent analyses and
identities. Pons currently checks explicit protocol traces; source-derived
typestate remains planned. Read
link:docs/PURPOSE-AND-PROOF.adoc[purpose, differences, limits and proof opportunities]
and link:docs/adr/0004-companion-to-panic-attack.adoc[ADR-0004].

== Status

*Implementation in progress toward v0.1.0.* Milestones M0–M4 are present: the
Rust workspace, scanning engine, six native tree-sitter grammars including PHP,
JSON 0.5.0 (0.4.0 frozen)/SARIF reporters, Python CFG/dataflow and a bounded PHP context-flow
slice. Thirteen source rules are registered (ten T0, three T1).
`pons scan <PATH>`, `pons catalogue`, `pons man`, `pons doctor`, `pons trace`,
`pons wharf-trace` and `pons validate-report` exist;
`pons.toml` suppression, inline allowances, rule/language
selection, `--explain`, `--no-speculative`, `--fail-on-skips` and required-language
coverage are implemented. Unsupported and opaque inputs remain visible; a
zero-file run exits 2. See link:docs/COVERAGE-MIGRATION.adoc[migration notes].

Still open for the v0.1.0 acceptance sweep: source-derived T2 typestate, T3
speculative rules, external-corpus precision/recall gates with confidence
intervals, optional local adapters, and a portability/release matrix. The
historical 27-check rookie-scanner audit describes a deferred fork, not the
current binary; see `docs/AUDIT.adoc` and `PROOF-PROGRESS.adoc`.

The ratified plan remains authoritative for design decisions not yet built;
where this status section and the plan disagree about what has landed, the
code and `PROOF-PROGRESS.adoc` are the measured source of truth.

== The one-line contract

*Never dress a heuristic up as a proof.* Every finding carries an evidence
class (`HEURISTIC` / `DATAFLOW` / `PROTOCOL` / `SPECULATIVE`), and
`SPECULATIVE` findings are visually demoted in every output format. Every
rule ships with a negative corpus that falsifies it; a rule that fires on its
own negative corpus is demoted or removed, enforced in CI.

== Estate metadata (for agents and tooling)

Repository facts and agent rules live in the estate's deed-era files:

* `pons-asinorum_chora.deed` — the repository's facts: identity, authority,
  routing, status sources, licensing policy.
* `0-AI-MANIFEST.deed` — the agent front door: purpose, routing, invariants
  (never dress a heuristic up as a proof; the falsifier gate; no silent
  skips), startup checklist, attestation.
* `coordination.k9` — the nerve receptor: what the repo emits, responds to,
  and guards (schema `k9-coordination` 1.2.0).

The legacy `.machine_readable/` descriptiles are frozen source pointers:
A2ML is retired estate-wide and must not be extended.
