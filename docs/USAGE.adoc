= Using Pons
:toc:

This page describes the binary on the current branch. Anything marked
*planned* is a design intention, not a command the executable accepts. A
machine drift test compares the commands and flags below with `pons --help`
and `pons scan --help`; a fake documented flag fails CI.

== Commands

[source,shell]
----
pons scan <PATH> [--format human|json|sarif] [--fail-on info|warn|error]
                 [--config FILE] [--rule ID]... [--lang python|javascript|typescript|tsx|rust]
                 [--no-speculative] [--explain] [--fail-on-skips]
pons catalogue
pons man
pons doctor
pons trace <EVENTS.json> --protocol <PROTOCOL.toml>
----

`scan` discovers files by extension and runs the registered rules. `.gitignore`
and `.ponsignore` are honoured. Build/VCS directories `.git`, `target` and
`node_modules` are skipped; directories named `corpus`, `third_party` or
`external_corpora` are *not* hidden by default, because a legacy-code exnovation
scanner must not silently ignore the estate it was built to inspect. Use
`.ponsignore` for an explicit exclusion.

`--lang` forces one grammar for a single file, including an extensionless file.
It is rejected for a directory. `catalogue` prints the live rule registry.
`man` renders a groff page from the same clap command model as `--help`.
`doctor` reports whether named optional adapter executables are on `PATH`; it
does not claim those adapters are integrated or tested.

`pons trace` checks an explicitly supplied, ordered JSON event trace against a
TOML finite-state protocol. It does **not** infer events from source code.
Events have non-empty `instance`, known `call`, positive non-decreasing `line`
fields. Unknown calls are errors, so a misspelt event cannot quietly make a
trace look complete. Exit 1 means protocol violations were found.

== Scan output and exit codes

`--format human` is the default. `--format json` emits the versioned envelope
from PLAN Appendix G; `--format sarif` emits SARIF 2.1.0 with an `invocations`
array. Skipped files/subtrees appear on stderr, in JSON
`scanned.skipped`, and in SARIF
`runs[0].invocations[0].toolExecutionNotifications`. A scan with skips still
exits 0 by default (ADR-0005), because it did complete; `--fail-on-skips`
turns any skip into exit 2 for estates that require complete coverage.

Exit codes:

* `0` — scan completed and no selected threshold was reached.
* `1` — a non-`SPECULATIVE` finding reached `--fail-on`; without `--fail-on`,
  output is advisory.
* `2` — invalid input, unopenable root, configuration/protocol error, or
  `--fail-on-skips` with at least one skip.

`--no-speculative` omits T3 findings and records them as filtered.
`--explain` adds evidence class and tier to human output. `SPECULATIVE`
findings are always demoted in all formats and never count toward a threshold.

== Encoding and locations

UTF-8 is the normal path. If a supported file is not UTF-8, Pons decodes it as
Latin-1 so its line structure survives, marks it as `transcoded`, and reports
that fact. Tree-sitter byte offsets then index the decoded string, not the
artifact. SARIF therefore *omits* `byteOffset`/`byteLength` for a transcoded
file; line and UTF-16 columns remain valid. The JSON envelope lists transcoded
paths. This is deliberately less impressive and more truthful than emitting an
offset that points at the wrong bytes.

Parse trees with tree-sitter error recovery are rejected as skipped files, not
treated as clean parses. A partial scan must never read as a clean one.

== Configuration and dismissals

Pons reads `pons.toml` at the scan root (or the parent of a single-file scan),
or the file supplied with `--config`. Unknown keys, unknown suppressed rule
IDs and invalid globs are operational errors. This is the accepted schema:

[source,toml]
----
[identity]
name = "pons-asinorum"
aliases = ["Pons"]

[suppress]
rules = []                    # non-empty broad suppression lists are rejected
paths = []

[[suppress.allow]]
rule = "while-true-no-break"
path = "examples/service.rs"
reason = "Intentional service loop; termination is external"
owner = "service-maintainer"
expires = 1798761600           # 2027-01-01 UTC; renew explicitly when reviewed
----

`identity` is reserved for future document-identity checks; it is parsed and
validated but does not currently generate findings. The `pattern`, `budget`,
`i18n` and `asset` tables described by the deferred 2026-09-09 rookie-scanner
fork are *planned*, not accepted by the current configuration parser.

In supported source languages, an actual comment on the finding's start line,
or the immediately preceding line, can contain:

[source,python]
----
# pons:allow self-assignment -- deliberate binding example | owner=maintainer | expires=1798761600
x = x
----

Only comment nodes count. A string containing `pons:allow` cannot suppress a
finding. Suppressed findings are counted in `scanned.suppressed_findings`, not
silently erased. Reason, owner and future expiry are mandatory. Fingerprints
are emitted in evidence contract 1.0.0; editor-style review remains planned.

== Planned commands (not in this binary)

The following belong to the deferred adapter slice and are marked explicitly;
they are not accepted by `--help`:

* `pons challenge FILE` — planned (M9): local Invariant Path hand-off, no
  annotation persistence.
* `pons extract FILE --via pandoc|ocr` — planned (M9): bounded document/image
  text extraction.
* `pons spell FILE --via aspell|hunspell` — planned (M9): dictionary misses,
  no automatic rewrites.
* `pons search PATTERN FILE --errors N` — planned (M9): approximate text search
  through `agrep`.

Optional adapters must remain explicit, locally invoked, time/output bounded,
and never run scanned project code by default.

== PHP portfolio upgrade

Native PHP parsing and three bounded rules are available. See
link:PHP-ADAPTER.adoc[PHP model boundary],
link:COVERAGE-MIGRATION.adoc[coverage/exit migration],
link:EVIDENCE-CONTRACT.adoc[evidence exchange and suppression migration], and
link:PROTOCOL-MODELS.adoc[explicit model premises].

`--require-language php` requires applicable PHP analysis without opaque scopes.
Haskell and Elixir remain unsupported. A zero-file scan always exits 2.
`--fail-on-skips` now includes unsupported source/configuration files.
`pons validate-report FILE` validates the machine envelope, not target safety.
`pons wharf-trace FILE` checks supplied events against the bounded Wharf model.
