= Echo Types scanner follow-up — 7 November 2026

== Scope and correction

The baseline is PONS `b9ab55c6973514a731c7659a2fbee21b5037b1ef`.
The source reproducer is echo-types `ebde9ac4e1a9f115b441c642c82aced1316c5983`,
`docs/echo-types/prototypes/warrant_debugger_prototype.jsx`.
Its valid SVG keyword attribute `in="SourceGraphic"` fails with upstream
JavaScript grammar 0.25.0. The final repair patches that grammar's JSX
identifier context, retaining modern `using` and `await using` declarations.
An earlier 0.23.1 compatibility pin is superseded because it lost that syntax.
There is no source rewriting, TSX fallback or acceptance of recovered error
trees. `vendor/tree-sitter-javascript/PATCHES.adoc` pins the upstream source,
generator, patch and generated output. The tree-sitter core and TypeScript/TSX
grammar remain unchanged.

When every supported source fails parsing, the report now says `partial`,
not `no-applicable-input`. Report validation independently rejects the old
misclassification for current reports; genuine frozen 0.4.0 artifacts retain
their old status semantics. SARIF marks completed parse-only scans as partial
execution with diagnostics. Unsupported Agda inputs remain explicitly unsupported;
this repair does not add an Agda analyser or constitute browser execution.

== Formal verification plan and trust boundary

Creusot with Pearlite contracts: `OPEN`, not run for this repair.
Verus: `OPEN`, not run for this repair. The Rust regressions above are tests,
not formal proofs of parser correctness or the coverage classification.
Pearlite is Creusot's specification language, not a third verifier.

The third-party grammar's JavaScript/JSX semantics remain a dependency
assumption (`ASSUMED`), with upstream commit, local patch and generator digest recorded in
`vendor/tree-sitter-javascript/PATCHES.adoc`. This is modified vendored
source; its path dependency has no registry checksum. The MIT licence is
unchanged. A future grammar update must pass the regressions, regeneration
check and complete existing suite before adoption.

== Review follow-up

The next patch extends JSX keywords to member names, removes the invalid
`export` expression alternative, and repairs CR-only and identifier-boundary
automatic semicolon handling. It includes the upstream parameter-highlight
query referenced by the grammar manifest. The receipt is
`0.25.0+jsx-keywords.3`.

`pons-core` directly depends on the vendored grammar so a downstream Git or
path consumer receives the same parser. It is explicitly non-publishable
until a distributable grammar package is provided; a root-only Cargo patch
cannot guarantee registry consumers receive the repaired code.

Report validation retains both historically accepted 0.4.0 zero-file
classifications when explicit coverage failures justify partial coverage.
Coverage and execution outcomes must still agree. Portable path checks
reject drive prefixes and escaping parents on every host, while permitting
non-escaping parent components. Default parse-only CLI coverage is exercised.
The generator download requires HTTPS for the original URL and redirects,
in addition to its pinned digest. Hosted PR checks record final verification.

The subsequent portability review preserves POSIX single-file basename
boundaries before display normalization. A successfully stripped scan-root
prefix distinguishes in-root colon filenames from drive-qualified paths that
were never inside the root. Both are checked independently of the reader host.
The updated Windows workspace suite passed 258 test executions; all-target
Clippy, eight parser regressions and the 116-parse upstream corpus passed.
The generator provenance is unchanged; the external scanner revision advances
with the explicit Unicode boundary repair.

The subsequent review identified ambiguous relative source paths. Normal CLI
scans (including forced grammars) and `Engine::scan` now use absolute roots,
so POSIX filenames resembling drive paths remain recognisable as POSIX input.
The reader derives relative Windows directory paths from their separators,
independently of its own operating system. Regression reports are rebased to
Windows relative syntax and validated on both hosted operating systems.

Historical path behaviour was checked against commits `6a20ca7` and
`84f58f9`: those implementations determined the parent before replacing
backslashes. On POSIX, a single file `/tmp/a\b.py` therefore produced
`a/b.py`, as the current regression requires. The later temporary early-
normalisation bug is not adopted as the frozen 0.4.0 format's semantics.
Old reports with intrinsically ambiguous relative roots lack explicit
producer-platform metadata. The reader preserves both POSIX and Windows
interpretations and requires the record path and semantic fingerprint to
agree on the same one. Native writers retain the original path behaviour.
This establishes internal consistency, not a unique historical filesystem
identity. Tests cover both 0.4.0 and 0.5.0 legacy forms and reject mixed
interpretations; the Windows workspace suite passed 261 test executions,
with all-target Clippy and the eight CLI contract tests passing.
