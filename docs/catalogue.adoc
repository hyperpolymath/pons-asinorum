= Registered Pons rules
:toc:

Reviewed snapshot of `pons catalogue`, which is generated from
`RuleRegistry::all()`. The drift test compares the rule IDs below with the live
registry. Ten rules are registered on this branch: eight T0 syntactic checks
and two T1 Python dataflow checks. T2 source typestate and T3 speculative rules
are planned, not registered.

== 1. `div-by-literal-zero`

division or modulo whose right-hand side is a literal zero.

Languages: python, javascript, typescript, tsx, rust.

Tier/evidence: T0 / HEURISTIC. Severity: WARN. Counter-condition: floating-point
semantics, overloaded operators, or deliberate failure tests.

== 2. `swallowed-error`

a catch or except block that discards the error without acting on it.

Languages: python, javascript, typescript, tsx.

Tier/evidence: T0 / HEURISTIC. Severity: WARN. Counter-condition: an
intentionally best-effort operation should use a documented allowance.

== 3. `self-assignment`

an identifier assigned to itself, doing no work.

Languages: python, javascript, typescript, tsx, rust.

Tier/evidence: T0 / HEURISTIC. Severity: WARN. Counter-condition: a deliberate
binding or generated shim may be intentional.

== 4. `constant-condition`

a literal boolean in a condition slot, so the branch is decided before it runs.

Languages: python, javascript, typescript, tsx, rust.

Tier/evidence: T0 / HEURISTIC. Severity: WARN. Counter-condition: a temporary
feature toggle or generated branch may be intentional.

== 5. `while-true-no-break`

an unconditional loop with no reachable break, return or throw.

Languages: python, javascript, typescript, tsx, rust.

Tier/evidence: T0 / HEURISTIC. Severity: WARN. Counter-condition: an
intentional service loop needs a scoped allowance; this is not a termination
proof.

== 6. `empty-effect-loop`

a loop whose body is empty or does nothing observable.

Languages: python, javascript, typescript, tsx, rust.

Tier/evidence: T0 / HEURISTIC. Severity: WARN. Counter-condition: iteration can
itself invoke effects through an iterator or generator.

== 7. `unreachable-after-jump`

a statement immediately after return, throw, raise, break or continue.

Languages: python, javascript, typescript, tsx, rust.

Tier/evidence: T0 / HEURISTIC. Severity: WARN. Counter-condition:
language-specific hoisting, macros or conditional compilation may make the
statement significant.

== 8. `string-concat-in-loop`

repeated string concatenation inside a loop, quadratic where a join is linear.

Languages: python, javascript, typescript, tsx, rust.

Tier/evidence: T0 / HEURISTIC. Severity: WARN. Counter-condition: small bounded
strings or runtime optimisation may make this harmless; no complexity bound is
inferred.

== 9. `dead-store`

a value stored and never read before it is redefined or the function ends.

Languages: python.

Tier/evidence: T1 / DATAFLOW. Severity: WARN or INFO depending on RHS effects.
Backward live-variable analysis over the Python CFG. Known conservative cases
include opaque functions, captures and `with` bodies whose context manager may
suppress an exception; see ADR-0002 amendment 2026-10-23.

== 10. `read-before-init`

a local read on a path where it may not yet be bound.

Languages: python.

Tier/evidence: T1 / DATAFLOW. Severity: WARN. Forward may-unbound analysis over
the Python CFG, with explicit pruning for unreachable predecessors, guaranteed
non-empty literal loops, and narrowly correlated pure `is [not] None` guards.
The analysis remains path-insensitive in general; see ADR-0002.
