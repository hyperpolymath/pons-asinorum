= Pons explained

Pons reviews the small oversights that remain when the code compiles: work
that does nothing, instructions that disagree, missing connections and
forgotten publishing details. Its explanations should help someone fix the
mistake without requiring specialist vocabulary.

The working development version is described in link:README.adoc[README],
link:ARCHITECTURE.adoc[architecture] and link:docs/USAGE.adoc[usage].
The original CFG/dataflow and source typestate milestones are still open;
link:docs/SCOPE.adoc[scope] separates them from implemented checks.

Each finding states its evidence. A supplied protocol can support conditional
resource arithmetic or a trace-state violation; it cannot make a universal
claim about executions that were not modelled. Use `pons scan . --explain`
for details and `pons scan . --format json` for machine-readable evidence.
The ordinary output stays practical and advisory.

https://github.com/hyperpolymath/panic-attack[panic-attack] is a separate
security/robustness companion. Other integrations are described in
link:docs/INTEROPERABILITY.adoc[interoperability]. Contributions follow
link:.github/CONTRIBUTING.md[the contribution guide].
